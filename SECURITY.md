# Security Policy

## Supported versions

HermesKey is young. Security fixes are expected to land on the latest `main` branch and the most recent tagged release.

## Reporting a vulnerability

Please do **not** open a public issue for security-sensitive problems. Use GitHub's [Report a vulnerability](https://github.com/graygarbage/HermesKey/security/advisories/new) form instead (GitHub sign-in required). Private vulnerability reporting is enabled: your report goes to maintainers, not into public issues. You can also find the form under the repository's **Security → Advisories** page.

Include the affected version or commit, minimal reproduction steps, impact, and any proposed mitigation. Use synthetic examples whenever possible; do **not** attach real recordings, transcripts, private file paths, tokens, or unredacted logs. Maintainers can request additional information privately if needed.

If GitHub's reporting form is unavailable, open a public issue **only to request a private contact route**—do not include vulnerability details there. We aim to acknowledge reports and coordinate a fix before public disclosure when possible.
