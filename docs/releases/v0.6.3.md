# HermesKey v0.6.3

This release tightens local recording state, configuration permissions and install diagnostics. It does not add telemetry, remote transcription or translation.

## Privacy and security changes

- **Private runtime only:** audio, recorder/overlay PID state and speech sockets must live directly in an owner-only user runtime directory. HermesKey no longer uses predictable shared `/tmp` paths if `XDG_RUNTIME_DIR` is missing; unsafe paths, symlinks and nonprivate existing files are refused. Recorder and overlay state now includes process start time so stale or unverifiable PIDs are not signaled.
- **Private config from first install:** the installer creates the HermesKey config directory with mode `0700` and the config file with mode `0600`; upgrades tighten permissions while preserving your existing settings. The advanced config opener applies the same policy and refuses symlinked config paths instead of following them.
- **No transcript in installation diagnostics:** the optional synthetic-audio verifier reports success or a non-content error without printing the transcription, including when a custom sample is supplied. Do not use real user audio for support reports.

## Upgrade

Once this release is published, run the standard installer from your graphical desktop session, without `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/graygarbage/HermesKey/main/scripts/bootstrap.sh | bash
```

**Stop any active dictation before upgrading.** Older PID-only recording state cannot safely identify a running process after this change, so HermesKey will discard stale state without signaling that PID. The installer preserves your config values, may tighten their file/directory permissions and restarts the user services. Check `hermeskey --version` (expect `0.6.3`), `hermeskey-doctor` and a harmless dictated phrase in a focused editor. On a normal KDE session, `$XDG_RUNTIME_DIR` is owned by your user with mode `700`. Custom `WAV`, `SOCK` or PID-state locations outside that private directory will no longer work; see [configuration](https://github.com/graygarbage/HermesKey/blob/v0.6.3/docs/CONFIGURATION.md).

HermesKey remains local-first, but strict offline model startup is a **separate** tracked improvement: a cached model may still trigger a metadata request ([#65](https://github.com/graygarbage/HermesKey/issues/65)). Clipboard backup, when enabled, may remain in desktop clipboard history ([#67](https://github.com/graygarbage/HermesKey/issues/67)). These changes do not claim to resolve every privacy/security concern.
