# HermesKey v0.6.4

This is a roll-up of the reviewed privacy, reliability, configuration and bootstrap hardening merged since v0.6.3. Inference remains local. There is no translation feature, remote inference fallback, transcript telemetry or automatic support upload.

## What's new

- **Strict offline speech, by choice:** After caching a model, enable **Strict offline speech model** in Settings → Speech (or set `HERMESKEY_OFFLINE=1` in the canonical config) and restart the speech service when prompted. A missing local model fails without downloading. This controls speech-model startup/inference, **not** the networked installer, pip or other apps. The Speech page keeps the switch visible when its explanatory text wraps. [Privacy and network contract](https://github.com/graygarbage/HermesKey/blob/v0.6.4/docs/PRIVACY.md).
- **Clear clipboard choice:** Settings → Input has **Privacy-first typing**, selecting type mode with no clipboard backup. The default backup remains **on** for reliable paste and Unicode support. KDE's Klipper history or a clipboard sync app may retain older dictated text; HermesKey cannot clear those entries. Clear them in those apps yourself if needed. With `ydotool` and backup off, unsupported non-ASCII text triggers a warning rather than silently copying or losing text. Clipboard-only mode always copies.
- **Less identifying local diagnostics:** hotkey events no longer record app/window IDs, device names, paths or transcript/audio lengths. Its local log rotates at 256 KiB with one previous file; older history is not automatically cleared. Speech-server errors use allowlisted categories. Native libraries, systemd and preexisting journal entries remain outside HermesKey's journal-retention control; inspect logs privately before sharing.
- **One config path:** installed hotkey, Doctor, Settings and both user services use `~/.config/hermeskey/hermeskey.env` even with custom `XDG_CONFIG_HOME`. A legacy custom-XDG file is migrated to the owner-only canonical location and archived privately; conflicting files or symlinks stop the upgrade rather than overwriting either config. `HERMESKEY_CONFIG` is a per-command CLI override, not a service override.
- **Bootstrap and test hardening:** release lookup and archive validation fail closed rather than substituting `main`. Reviewed release SHA-256 values are pinned in bootstrap code and checked before extraction; new releases need a separate reviewed digest update. Speech dependencies have exact reviewed version pins, binary-only installs and no automatic pip/wheel upgrade. CI enforces offscreen Settings coverage and checks clean speech dependency installs. Release archives now contain only reviewed tracked files and build reproducibly from a clean Git commit. [Dependency/trust limits](https://github.com/graygarbage/HermesKey/blob/v0.6.4/docs/DEPENDENCIES.md).
- GitHub private vulnerability reporting is enabled; use the Security tab for sensitive findings rather than public issues.

## Upgrading on KDE

**Finish any active dictation first.** Bootstrap/installer refuse to upgrade while recording and do not stop or copy speech automatically. The installer preserves your config values, may archive a legacy custom-XDG config and restarts both user services. If canonical and legacy configs differ, resolve the conflict privately before retrying. Review [installation](https://github.com/graygarbage/HermesKey/blob/v0.6.4/docs/INSTALL.md) and [configuration](https://github.com/graygarbage/HermesKey/blob/v0.6.4/docs/CONFIGURATION.md) for migration and custom-venv details.

**Important release-asset timing:** The standard bootstrap intentionally refuses a *newly published* v0.6.4 asset until its independently reviewed SHA-256 is added to the bootstrap script in a separate PR. Wait for that digest update before running the normal install command. Never assume `--main` is a verified substitute: it deliberately installs mutable, unpinned code. Even after the digest update, the convenient `curl | bash` entrypoint comes from mutable `main`; review a bootstrap script fetched at a trusted immutable commit for stronger source pinning. Pinning package versions does not verify PyPI wheel bytes.

After the reviewed digest is available, upgrade from your graphical session without `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/graygarbage/HermesKey/main/scripts/bootstrap.sh | bash
```

Check `hermeskey --version` (expect `0.6.4`), Settings → Speech/Input/System and `hermeskey-doctor`. Confirm a harmless local dictation and typing into your chosen editor; never post audio, dictated text, config contents or raw journal output in public reports. A bundled synthetic WAV is used by bootstrap's speech check, not your microphone. The sole visible KDE launcher remains Settings; existing pinned legacy desktop IDs are retained.
