# HermesKey v0.5.2

This patch release makes Wayland typing and rapid hotkey presses more reliable.

## Highlights

- **Typing daemon recovers after login.** On systems where `/dev/uinput` becomes accessible only after a graphical login, `hermeskey-ydotoold.service` now retries at a slower rate rather than exhausting systemd's restart limit before access is granted (#43). The doctor also checks `/dev/uinput` access. If access never appears, see [troubleshooting](../TROUBLESHOOTING.md); the daemon is not run as root.
- **No overlapping recordings or lost transcripts from rapid presses.** Hotkey actions now use a per-user lock through recording start/stop, transcription, and insertion. Extra presses during those transitions are ignored with a notification; the next press after recording starts still stops it (#44). An automated concurrency test covers this behavior.
- **More audio troubleshooting guidance** for recording problems (#41).

## Upgrading

After the GitHub release is published, rerun the standard installer to install this tagged release:

```bash
curl -fsSL https://raw.githubusercontent.com/graygarbage/HermesKey/main/scripts/bootstrap.sh | bash
```

The installer restarts the user services. It leaves your existing `~/.config/hermeskey/hermeskey.env` unchanged. Check `hermeskey --version` and `hermeskey-doctor` afterward.

## Release-candidate test

Before the tag is published, install system dependencies using [INSTALL.md](../INSTALL.md). The local `./install.sh` copies HermesKey files but **does not create a Python venv or install its dependencies**. On a fresh machine, set up the venv explicitly after checking out the release-prep branch (or use your existing configured venv):

```bash
gh repo clone graygarbage/HermesKey
cd HermesKey
git switch release/v0.5.2-prep
python3 -m venv ~/venvs/stt
~/venvs/stt/bin/python -m pip install -U pip wheel
~/venvs/stt/bin/python -m pip install -r requirements.txt
./install.sh
hermeskey --version
hermeskey-doctor
```

Do not rerun the default bootstrap installer *after* `./install.sh`: before the tag is published it reinstalls v0.5.1. If `hermeskey-doctor` says the venv is missing, the speech service cannot start; create it and restart `hermeskey.service` before testing dictation.

Confirm that `hermeskey --version` prints `0.5.2`, record and transcribe with several rapid presses, and reboot to check that `hermeskey-ydotoold.service` becomes active. Report any failures before tagging.
