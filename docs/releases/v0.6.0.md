# HermesKey v0.6.0

HermesKey now has one Settings window for everyday configuration and local troubleshooting. The hotkey remains the way to dictate; you do not need to keep Settings open.

## What's new

- **Speech and input settings:** choose a microphone, model and **spoken** language (including Auto-detect); set typing or clipboard mode, clipboard backup and focus safety. Toggle the overlay and sound cues. This transcribes what you say—it does **not** translate speech into a selected language. A model change may require a download when the speech service is restarted, not when you select it.
- **System page:** see whether the speech model and typing daemon are ready, request a service restart, run Doctor, read a bounded excerpt of local logs, or open the advanced config file. Save or discard GUI changes before editing the file externally. Logs are not uploaded; review them before sharing.
- **One KDE app-menu entry:** HermesKey Settings replaces the scattered utility entries. The old desktop IDs are still installed but hidden so existing pinned shortcuts can keep working. The old Control Center shortcut now opens Settings; CLI diagnostic commands still work.
- **More reliable setup:** bootstrap checks system requirements and the speech environment, waits for the model and verifies transcription with bundled synthetic audio (no microphone recording or typing). Doctor validates configuration settings.
- **Unicode insertion and diagnostic privacy:** non-ASCII text that `ydotool` can silently drop is pasted when clipboard backup is allowed; otherwise HermesKey warns without changing the clipboard. Speech-server failure logs no longer contain raw exception messages or request contents.

## Upgrade or install

After this release is published, use the standard installer from your graphical user session, without `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/graygarbage/HermesKey/main/scripts/bootstrap.sh | bash
```

The installer preserves your existing `~/.config/hermeskey/hermeskey.env` and restarts the user services. On KDE, look for **HermesKey Settings** in the app menu. Keep your dictation hotkey bound to `~/.local/bin/hermeskey`. Check `hermeskey --version` (expect `0.6.0`) and `hermeskey-doctor`, then record and transcribe into an app you choose. See [installation requirements](https://github.com/graygarbage/HermesKey/blob/v0.6.0/docs/INSTALL.md) if preflight reports missing system packages or `/dev/uinput` access.

## Current limitations

- Settings edits the canonical `~/.config/hermeskey/hermeskey.env` because the speech service uses that path. Custom `XDG_CONFIG_HOME` configurations are not yet consistently respected across the installer, hotkey, GUI and services ([#57](https://github.com/graygarbage/HermesKey/issues/57)). Check which config the service reads before upgrading a customized installation.
- With `COPY_TO_CLIPBOARD=0`, non-ASCII `ydotool` output is not inserted automatically rather than silently changing the clipboard. Enable clipboard backup for Unicode paste fallback; see [configuration](https://github.com/graygarbage/HermesKey/blob/v0.6.0/docs/CONFIGURATION.md).
- The Settings window needs your distro's system PySide6 QtWidgets package. It is not installed by the Python speech venv; [install instructions](../INSTALL.md) list the required packages.
