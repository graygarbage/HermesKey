# HermesKey v0.6.2

This security maintenance release tightens which local typing-daemon socket HermesKey will trust. It follows the v0.6.1 process-argument and Doctor privacy fixes.

## What changed

- HermesKey no longer falls back to a socket in shared `/tmp` when the user-owned `ydotoold` socket is missing. The typing socket must be owned by your user, directly inside your private runtime directory, and accessible only to you; symlinks and overrides outside that directory are refused.
- If no trusted socket is available, HermesKey does **not** send typing or paste commands there. With `COPY_TO_CLIPBOARD=1` (the default), an existing clipboard backup remains available for manual paste. With backup disabled, nothing is inserted or copied. A notification explains why typing was refused.

This is a local trust-boundary fix; it does not introduce remote inference, tracking, or telemetry. Other security and privacy work is tracked separately.

## Upgrade

Once this release is published, run the standard installer from your graphical desktop session, without `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/graygarbage/HermesKey/main/scripts/bootstrap.sh | bash
```

The installer preserves your existing `~/.config/hermeskey/hermeskey.env` and restarts both user services. Check `hermeskey --version` (expect `0.6.2`) and `hermeskey-doctor`, then dictate a harmless phrase into a focused editor. Confirm the phrase appears in the editor, not only on the clipboard.

On a standard KDE user session, `$XDG_RUNTIME_DIR` should be owned by you with mode `700`, and its `.ydotool_socket` should be owned by you with mode `600`. Custom `YDOTOOL_SOCKET_PATH` values outside that private runtime directory will no longer work; see [configuration](https://github.com/graygarbage/HermesKey/blob/v0.6.2/docs/CONFIGURATION.md). Do not loosen socket or `/dev/uinput` permissions to work around a failed check.
