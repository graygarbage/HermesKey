# Speech dependency policy

Bootstrap installs the exact reviewed speech runtime versions in [`requirements.txt`](../requirements.txt), including transitive packages. It does not upgrade pip or wheel automatically. Installs are binary-only: if a supported wheel is unavailable for your Python/architecture, setup stops rather than building an unreviewed source distribution. An existing venv may contain unrelated packages; `pip check` rejects conflicts but this is not an isolated lock of those unrelated tools.

The version pins bound dependency drift across installs of the **same source revision**. They are **not per-wheel SHA-256 pins or signatures**: bootstrap still trusts the PyPI index, TLS, and wheel publisher for artifact bytes. This does not imply an offline installation. CI installs the pins in a clean Ubuntu 24.04 / Python 3.12 venv and checks imports; the developer also tests fresh installs on supported KDE/Python versions before a release. Python packages are not downloaded by strict-offline speech inference, but bootstrap is an explicit networked setup step. The UI's system PySide6 package is installed by the distro, not in the speech venv.

For a security update, review the advisory and the new direct/transitive versions, update `requirements.txt` in a separate PR, run clean-venv CI and KDE install/upgrade checks, then follow [`RELEASING.md`](RELEASING.md) before tagging a release. Users who intentionally manage a custom Python environment may use `--skip-venv`, but they are responsible for its integrity and compatible versions. Do not silently replace pinned packages with an unreviewed newer range or claim a same-version wheel is independently verified without hashes/signatures.
